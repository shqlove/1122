# 抖音手机发布

从工作台「技能大全 → 抖音发布」开始核对。工作台以最近一次分发记录为本批计划，逐台锁定已核验发送的成片。读取每台的 `target`，用其中的成片名、USB 文件名和 SHA-256 核对实际相册素材。旧草稿或上次发布页可能还停在别的片，选片以本批目标和实际图库核对结果为准。

分发和发布共用工作台的全局发布台账。用视频 SHA-256 识别同一文件，用工作台记录的 `sourceSha256` 识别可靠对应到同一源视频的重导版本。任意账号已经核实发布的成片跳过后续分发和发布，回传原手机也跳过。处于上传中、审核中或提交结果待核查的成片仍可分发，暂停新的发布提交，先核实原账号结果。

## 1. 核对视频和账号

1. 读取绑定、在线状态和当前画面。在「照片 → 图库」定位本批目标，核对封面和时长，再通过详情页读取相册文件名，通过 USB 核对原片 SHA-256。相册有其他旧片时仍可核对本批目标。目标缺失、无法唯一定位或哈希不符时记为阻塞，留待重新核对。只有工作台没有分发历史时，才使用图库中唯一能核实身份的可见视频。Panda Helper 导入名可能显示为 `tempVideo_…`，而 USB 使用 `IMG_…`。DCIM 也可能列出「最近删除」中仍存在的文件。以与当前图库目标画面及时长实际对应、且通过哈希校验的候选为准。
2. 通过台账查重后，打开抖音，从「我」核对当前账号名称和抖音号，记下发布前的作品列表。如果账号与用户指定的不符，报告该手机阻塞。对于台账之外疑似手动发布的作品，核对账号作品并说明证据与不确定性。单凭相同封面不足以确认重复。点击底部「＋」进入「相册」，选中与图库核对过的视频。在还显示唯一已选视频、缩略图和时长的选片页停下，等用户确认后再点「下一步」。
3. 报告逐台核对结果，包括手机、账号、文件名、时长、来源、是否适合发布及拟公开发布的范围。最近一批未给该手机分发、分发尚未核验、给该手机分发了多个目标、设备离线或账号和目标无法确认时，列出具体阻塞。同一份成片分发给两台手机时，只有首个完成核对的目标可进入待确认发布，另一台说明本批重复。

## 2. 等待用户确认本次清单

展示逐台核对结果，只把通过项列入本次公开发布清单。等用户确认本批目标手机、账号、视频和可见范围后再发布。独立运行时也先展示本次清单并等待确认。

## 3. 发布并记录结果

1. 用户确认后，针对确认通过的手机重新截图。先复查该视频的发布台账和选片页，再点「下一步」核对预览并进入最终发布设置。保留成片与原声，未指定的标题、描述、话题和定位留空，封面使用默认帧。已有生成素材证据时，选择「添加自主声明 → 内容由 AI 生成」并核对回显。核对「公开 · 所有人可见」和「发作品」按钮。选片页变化或发布设置无法可靠确认时，报告具体情况。
2. 点一次「发作品」。页面也可能有「限时日常」，作品发布入口的文字是「发作品」。截图检查抖音反馈，出现「发布成功」后回同一账号作品列表，用封面、出现顺序和发布前列表核对新作品。
3. 按手机保存抖音账号、相册显示名 `album_filename`、已匹配的 USB 文件名、源视频 SHA-256、时间、可见范围和实际发布状态。只看到「上传中」或「审核中」时记录对应进度。遇到疑似重复、发布阻塞或结果不明，先查原账号作品列表并报告具体情况。按钮结果不明时避免重复点击。

技能到发布结果核验为止。如需移出手机上已核验发布的原片，由用户单独启动「技能大全 → 清理已发布原片」。

## 工作台工具

工作台将每轮工具限定在一台手机。用 `phone_open(app)` 打开 `photos` 或 `douyin`。用 `phone_screen()` 获取实际画面和 `observation_id`，以这个编号调用 `phone_gesture(observation_id, kind, x, y)`。点击用 `tap` 和 0–100 的百分比坐标，滑动用 `swipe_up` 或 `swipe_down`。每次输入前查看最新截图，遇到界面变化、旧草稿、权限弹窗或点击无反应时重新观察。操作结果以画面为准。

- 核对时，把图库详情里的文件名交给 `phone_verify_media(filename)`。如果工具返回 `needs_visual_match`，按参考画面及精确时长与当前图库视频比对，必要时在「照片」播放查看特征帧。只有唯一匹配时才用 `phone_verify_media(filename, dcim_filename)` 验证该候选，读取返回的 `filename`、`media_sha256` 与 `generated`。用最新选片页截图调用 `phone_record(status, detail, account, video, media_sha256, observation_id)` 记录 `ready`。其中 `video` 用工具返回的 USB 文件名，`detail` 包含时长和缩略图特征，`account` 填当前账号昵称和抖音号。缺少可靠证据时用 `blocked` 说明原因。
- 用户确认本次清单后，先截图并用 `phone_resume_prepared(observation_id)` 复核选片页，再进入最终发布设置。核对封面、声明、可见范围和按钮后，用同一个账号、原始文件名和哈希及当前截图 ID 调用 `phone_record` 记为 `armed`。重新截图，用 `phone_submit(observation_id, x, y, account, video, media_sha256)` 在画面所示「发作品」处提交一次。普通手势只用于导航和结果复查。
- 提交后用 `phone_record` 与核验实况截图的 `observation_id` 记录结果。已经证实出现在原账号作品页时记为 `published`，正在上传或审核中记为 `reviewing` 并注明画面显示的状态。查不到可信结果时保留待核查状态。

## 独立运行回退

从对话视频工作台项目根目录使用 `.venv\Scripts\python.exe`。用 `dialogue_tool.settings.settings()` 读取工作台配置，以相同的 `data` 创建 `dialogue_tool.douyin_publish.DouyinPublish`，并读取已绑定手机和发布台账。使用 `dialogue_tool.douyin_agent.run_batch` 执行两段流程，Codex 路径使用配置里的 `codex`。

1. 用 `publisher.begin(slots)` 建立预检查批次，执行 `run_batch(publisher, batch, codex)`。读取 `publisher.state()["batch"]`，展示当轮核对清单，等待用户确认其批次 ID。
2. 收到确认后，用 `publisher.confirm(batch_id)` 继续同一批次，再交给 `run_batch`。最终点击由 `DouyinPublish.submit` 执行并写入台账。确认与发布结果以同一工作台台账为准。

01 号和 02 号的界面布局可能不同。分别观察账号、选片页、AI 声明和最终按钮的位置。每步用当前画面定位，互相独立地核验和汇报。

# 对话视频生产工作台

Windows 11 x64（无独立显卡）/ macOS 开发验证版。GitHub 仓库标识为 `dialogue-video-production-workbench`，Python 包及启动入口名称保持兼容。

当前主界面使用 React + shadcn/ui，提供素材总览、项目、图片组、视频生成、我的任务、后期制作、成片库和设置。素材总览支持跨项目选图及每组直接生成；H3/即梦任务独立准备、逐条确认费用并提交，记录实际提示词、参考素材、状态和本地输出。长台词按语意分两条生成，下载齐全后 FFmpeg 合并原片。字幕、空间效果与 BGM 属于用户另行启动的后期阶段。

这是需要本机依赖的桌面开发版，不是免依赖安装包。付费服务需用户本机登录或配置密钥；本仓库不保存凭据、项目数据库、聊天、业务视频或参考音频。

### 当前工作台流程

1. 项目页导入并分析视频，在图片组页复核人物与图片。
2. 在图片组或素材总览点击“生成视频”，核对所选来源、图片、音色及提示词。
3. 添加独立任务并报价，检查参考图后逐条确认费用；其他项目或 Agent 的工作不阻塞新任务。
4. “我的任务”逐条查看所有历史提交；下载和合并后的原片在素材总览。下载失败保留“待处理”，需显式查询原任务，不重新付费。
5. 选择原片送后期，点击“开始 / 继续后期”才执行字幕、空间效果和 BGM，导出后到成片库验收。

### 源码仓库与本机资源

- 成功模板的原始参考音频仅保留在已配置的本机：`dialogue_tool/resources/h3-first-v1/voice.mp3`。新机器需恢复用户持有且 SHA256 与 `baseline.json` 一致的文件；也可使用手动参数及图片组自有音色。不要用测试音频替代生产音色。
- 后期程序是独立本地依赖，默认在相邻的“视频后期处理”目录，可用 `settings.local.json` 的 `postprocess_root` 指定。需它自己的 `流程配置.json`、阿里云凭据及 BGM；缺失时工作台明确显示不可用。
- 前端：Node 22，`npm ci --prefix frontend`，`npm run build --prefix frontend`，`npm test --prefix frontend`。测试前需 Python 环境（Windows 默认 `.venv`，也可设置 `PYTHON`）。前端构建产物位于 `dialogue_tool/ui/app/`。
- Python：`python -m pip install -e '.[test,desktop]'`，`python -m pytest -q`。无业务音频的 CI 使用 `WORKBENCH_TEST_SYNTHETIC_VOICE=1`，仅在测试进程里临时注入合成音频；FFmpeg 合并测试仍处理真实视频文件。
- CI 覆盖 Python 回归、Windows CPU 冒烟、React 构建、桌面接口合同及浏览器交互；不会付费生成视频。

以下为原始安装和分析功能说明；主界面流程以上述多页工作台为准。

## 打开与使用

**客户 Windows 11：** 在仓库目录运行 `setup_windows.ps1` 完成 Python 环境安装，按文档安装 FFmpeg / Codex / 即梦 CLI、登录账户，再双击 `start_windows.bat` 打开软件。详见 [Windows 11 无独显安装与验收](docs/Windows11无独显安装与验收.md)。

**Mac 开发机：** 双击 **对话视频工具.app** 或 **启动Mac工具.command**。目前两端都属于开发启动版，**不是免依赖 EXE 安装包**。

1. 点击“导入视频”，选择本机文件。原视频保留原位，不覆盖。
2. 可填写分析起止秒数；结束时间留空表示分析整部视频。
   已扫描的项目可直接点击“全部镜头”，在软件内浏览所有镜头代表图，点击放大并用上一/下一镜头切换；浏览不会启动 AI 分析。
3. 点击“开始拆解”。程序逐帧扫描镜头、提取候选，先由 Codex 分批找连续交流的候选片段（附两个人物锚点），跨批合并同段重复，再从该片段不同镜头选一组最佳 A/B，准备原尺寸截图。界面直接显示每组两张的结果，候选帧默认收起。
4. 同场同两人的连续交流合并重复组；一对多交流按不同对象分别建组，允许共享目标人物锚点。确定交流范围后，在完整候选池中选清晰、无遮挡的正反打。目标人物身份完全不确定时，保留画质与交流关系合格的组并标记 `uncertain`，供用户复核；收费生成前仍须确认角色位置。这些是视觉配组，不代表实际说话人或口型识别。
5. 不满意时点击“更换截图”，选 A 或 B，再点候选帧。两侧不能使用同一帧。更换后该组进入待确认，点击“确认这组截图”后回到结果列表。候选每页 32 张，可横向滚动或翻页；左侧 ＋ 可手动配组。
6. 在右侧填写每组提示词，失焦自动保存，也可点击顶部“保存”。切组、切项目及导出前会等待保存完成。右侧新增“即梦视频生成”区：配置全局提示词和视频模型，依次准备草稿、查询积分、明确确认后提交、查询、下载。仅填写提示词不会调用即梦。
7. 如需修复，选择 A 或 B，点击右侧圈选按钮，在原图上框选区域并执行本地 LaMa。完成后可通过“查看原图 / 查看修复图”对照。
   向制作 Agent 要求“去水印”时，默认一并去除指定范围图片上的叠加字幕；只有字幕也直接处理，无需再次确认。明确要求保留字幕时按要求保留，修复后检查结果。
8. 勾选要交付的组，点击“导出图片组”，选择输出位置。每次新建独立目录，不覆盖旧版。

已扫描项目的时间范围固定；更换范围时将视频导入为新项目。处理中请保持软件打开，原视频不要移动或修改。成功的识别、去重与二次复核结果会按新版本的缓存键缓存；断网、额度不足或重启后点击“继续拆解”，复用本版本已完成步骤。未完成的在途请求可能需要重新执行。额度不足时不会自动重试或切换付费服务。

本地扫描逐帧检测切镜。目标人物项目先每镜头选代表图、长镜头按最长12秒窗口补点；角色命中、不确定或缺少结果的镜头均扩展前后各2个镜头，再做交流识别。无目标人物项目沿用首、中、尾及约每6秒取样。交流范围确定后，从完整候选池精细选图（每组最多24张候选），不以稀疏代表图代替最终原尺寸截图。当前协作规则以 `AGENTS.md` 为准。

长片需要足够的 Codex 账号额度。已有约 92 分钟视频的完整本地扫描实测，但尚未完成约两小时真实电影的全片语义配组验收，处理时间和准确率不能据短片测试保证。详见 [批量截图验证记录](docs/批量截图验证记录_20261102.md)。

界面布局参考 [Spacedrive](https://github.com/spacedriveapp/spacedrive) 与 [InvokeAI](https://github.com/invoke-ai/InvokeAI)，未复制上游代码、未引入其框架或在线资源。

## 标准正反打筛选规则（2026-11-02）

- **先对话片段，后 A/B：** 按连续交流与参与人物划分，不按镜头切换拆组。同一段 A/B/A/B 反复切换，只保留一组；新的独立对话段即使人物相同也另出一组。
- **优先可生成质量：** 两张都应有不同真人的清晰脸部、明确单人主体、近正面、少遮挡、稳定构图；优先从整个片段而不是仅初始锚点镜头中挑选。
- **不凑图、保留人物不确定项：** 缺少独立视角或交流证据的候选保留排除原因；仅目标人物身份无法判断、但画质及交流关系合格的组标为 `uncertain` 并保留供复核。收费生成前必须确认人物侧。
- **覆盖边界：** 当前依赖画面候选与 Codex 视觉理解，不做语音转写或口型识别；完全没被识别为候选的对话不能凭本报告推算漏检率，更不能保证任意长片 100% 找全。
- 详细定义见 [标准正反打拆组规则](docs/标准正反打拆组规则_v1.md)。

## 导出内容

每组一个文件夹，包含 A/B 原始 PNG、已完成的修复 PNG、A/B 用于生成的 PNG、相应遮罩及提示词。根目录的 `manifest.json` 记录原片时间点、选图及处理版本。

尚未修复的图片按原图导出，清单会标为 `original`；不会将未处理图片标成“已去水印”。导出回到原片提取完整尺寸，候选缩略图不代替正式图片。

## 运行环境

- 已有 macOS 实测记录；Windows 11 x64 无独显适配有安装/启动脚本及 CI 冒烟测试，但需在客户真实 Win11 电脑验收。独立 Python 3.11 虚拟环境。
- Codex 使用本机应用内有效 CLI 路径，不修改全局 MkBoard 桥接，也不复制登录凭据。
- FFmpeg、FFprobe 用于读取视频及提取完整尺寸截图。
- LaMa TorchScript 模型使用 CPU，局部修复效果需要看图检查；没有自动接入在线图片服务。
- 即梦生成由单独安装、已登录的 `dreamina-canvas` CLI 执行，官方支持 Windows PowerShell 安装；首次在客户电脑运行需登录、确认会员/积分权益，批量运行在界面显示额度上限供人工批准。
- 如需改路径，在项目根目录建立 `settings.local.json`，可配置 `codex`、`ffmpeg`、`ffprobe`、`model`、`data`、`dreamina_canvas`。不要在该文件写入账号令牌。

# 优云智算 MiniMax H3 API

支持工作台生成面板和内置 AI 的同一套准备、报价、确认、查询、下载流程。
每个新生成轮次先选择渠道：聊天中出现“即梦 / 优云智算 H3”选择卡，手动面板也提供渠道下拉框。未选择时不能配置或准备新任务；已有草稿或任务不能直接切换渠道。
选择 H3 后默认 `MiniMax-H3`、15秒、768P、16:9；即梦默认 Seedance 2.0 Fast、15秒、720p、4:3。H3支持4–30秒。
两种渠道使用各自的真实账户积分，共用费用确认、提交前余额复查、原任务查询和下载回填流程。费用卡显示渠道、规格、余额及不足金额。H3当前没有服务端报价/消费封顶参数，界面注明文档估算，实际折扣与结算可能不同。
两张图片以 `reference_image` 提交，不作为首尾帧；本地素材通过 Data URL 传入。
`@男主`、`@聆听者`、`@音色` 会绑定实际图片/音频标签。默认禁止字幕、保留音轨、开启提示词优化。
按用户已验收的设置，后续 H3 生成统一开启 Context-IR（`use_context_ir=true`）。新轮次及选择 H3 渠道自动开启，不继承旧任务的关闭配置；历史记录保留原参数。仅当用户之后明确要求时，为指定测试关闭。
提示词要求不能保证模型完全遵循，成片仍需检查字幕和台词。

Windows 双击 `配置H3密钥.bat`，在本机隐藏输入中粘贴视频工作台专属的 `sk-ml-` 密钥。
或使用 `python -m dialogue_tool h3-set-key`。密钥存放在用户目录 `.dialogue-workbench/compshare-h3.key`，不进入项目或聊天。
也可配置服务进程环境变量 `COMPSHARE_H3_API_KEY`，或在 `settings.local.json` 设置 `compshare_h3_key_file`。
`python -m dialogue_tool h3-check` 仅查询可用积分，不生成视频。
修改代码后需重启工作台；密钥文件每次请求读取，修改文件后不需重启。

H3 使用视频工作台独立积分。当前文档输出每秒费率为480P=5、768P=10、1080P=19、2K=20、4K=22；每条提示词优化另收5积分。
工作台当前仅提交两张参考图及可选参考音频，不提供参考视频入口；图片和音频不额外收费。
报价采用文档费率，提交前再查余额。费率变化时需同步更新 `dialogue_tool/compshare.py`。
输入音频须为2–15.08秒。1080P及以上是后置超分，实际交付档位保存到任务的 `actual_resolution`。

本地草稿不上传、不扣费；用户批准积分卡后才发送素材和生成请求。
提交前保存幂等键，成功响应后保存平台任务ID。网络异常不会自动重提；若没有获得平台ID，需核查平台任务并按原幂等键恢复，不能新建轮次重复扣费。
任务成功后查询最新下载地址，校验视频、时长和音轨，再回填原图片组。此检查不代表已验收口型、台词或字幕。
官方文档：https://www.compshare.cn/docs/minimax-h3/api/minimax-h3-video-api


桌面成片归档：即梦与H3下载校验成功后，自动复制到系统实际桌面下的“豪哥视频”。按每批提交时间、项目、渠道建立目录，文件标注图片组号及提交标识。历史批次没有提交时间时采用原成片文件时间。同批后续下载加入原目录，重复下载不重复复制；用户修改过的桌面文件不会被覆盖。项目原片与关联保留，归档路径记录在任务archive_output。可用settings.local.json中的video_archive自定义目录。

下载与归档按单条隔离：成功项立即保存及归档，单条失败不阻断其他组；错误记录在任务 `download_error` 和本批 `download_errors`，重试沿用原任务。归档失败后仅重试复制，不重新生成或下载已完成项。字幕、空间效果和配乐由“视频后期处理”程序承接，现已集成到工作台“后期制作”和“成片库”，仅处理用户勾选的原片，不安装自动监视任务。
# 先配音再生成 H3 视频

在生成设置勾选“先生成完整配音，再自动生成 H3 视频”，或要求制作 Agent 开启 `audio_first`。完整台词使用 `台词：“原文”` 标注，主角参考音色沿用本组已绑定文件。单条支持 4–15 秒；更长的完整配音不能直接作为 H3 音频参考。

工作台将 IndexTTS 的实时配音报价与 H3 视频估算合并到一次费用确认。确认后自动生成完整配音，保留原始 WAV，以不变调加速适配目标时长（不截断、不删句），检查可解码和非静音，再将整段新配音送入 H3。没有配音试听确认步骤。长台词会加快语速；若本地适配仍需超过 2 倍加速则停止视频提交并保留配音。参考音频仍是生成指导，H3 不保证原样复制配音，成片声音和口型需要验收。

配音及视频分别保存稳定请求标识。应用重启后查询原任务即可继续；配音失败或素材变化会阻止后续视频收费。原始音色不会被生成配音覆盖，生成音频保存在项目 `generated-audio`，视频请求记录保存实际上传音频的路径、哈希和配音任务编号。



## 白色多页工作台（2026-11-13）

主界面使用 React + [shadcn/ui](https://github.com/shadcn-ui/ui)（MIT，源码及许可见 frontend），本地编译打包，无需远程页面或开发服务器。

- 项目：导入视频后在页首点击“分析视频”，可指定时间范围或仅扫描候选图；未分析项目直接进入此入口，图片组页也提供返回入口。
- 图片组：人物A/B预览、编辑台词和人物描述、候选换图、框选去水印/字幕、音色绑定。
- 视频生成：参数、共用提示词、Context-IR、费用确认卡、生成历史、原片预览与送后期。
- 后期制作：明确选择原片，ChatCut真实字幕→本地空间效果→统一BGM，任务状态持久化；修改SRT另存版本。
- 成片库：预览全部输出和版本，打开文件位置，手动标记/撤销验收。

右侧创作助手可收起，共用工作台持续会话并支持后期工具。切换项目保留聊天历史、模型选择和未发送文字；正在运行的一轮固定处理原项目，下一条消息使用当前项目与勾选组。项目附件仍按项目隔离。只有点击“开启新对话”才归档并重置会话；旧项目聊天首次使用时合并读取，原文件保留。切页不取消后台任务；本地后期进程在关闭窗口后继续。启动状态超过90秒无心跳会提示中断，重新选择原条目可复用已完成步骤。已导出与已验收分别记录。

前端开发：在 frontend 运行 npm install、npm run build。后端使用原有 `.venv\Scripts\python.exe -m dialogue_tool desktop` 启动。后期默认目录为工作台同级“视频后期处理”，可通过 settings.local.json 的 postprocess_root 指定；请求记录保存于该目录 workbench-runs。

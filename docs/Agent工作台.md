# 工作台内置 Agent

右侧「制作 Agent」使用本机 Codex 登录，通过官方 App Server 连续对话。模型目录和思考强度来自实际安装的 Codex，不把聊天模型与即梦视频模型混在一起。当前接入已用 Codex `0.166.0-alpha.5.1` 实测；动态工具属于实验协议，升级后如果连接报错会显示原因，不会自动重放任务。

## 使用

1. 选择项目和图片组。右侧选择聊天模型、思考强度。
2. 选择任务范围：当前图片组、已勾选且已确认的组、全部已确认组。下方显示准确组号。
3. 在右侧输入任务，点击发送或 Ctrl+Enter。发送前会保存左侧尚未保存的提示词。
4. Agent 读取真实项目和图片，通过工作台工具修改数据。左侧随数据变化刷新。可在回复中追问或纠正；停止不会撤销已经完成的操作。
5. 请求生成时，Agent 准备草稿并报价。核对聊天中的组号、数量、时长、模型和积分上限后，点击批准本批次。提交后最多自动查询约 20 分钟（另加远程调用耗时），完成的视频下载到原图片组。查询失败、超时或关闭应用后，可再要求「查询原任务并下载结果」，不要重新提交。

示例：

> 对选定组共用下面这份提示词，使用 Seedance 2.0 Fast、全能参考、15 秒、4:3。逐组看图确认豪哥在 A 还是 B，将豪哥绑定为 @男主，另一视角绑定为 @聆听者，沿用组02的豪哥音色绑定 @音色。先把提示词和绑定保存好，不提交。

> 检查这些组的最终执行单。没问题就准备草稿，返回本批次积分报价。

> 查询刚才那一批的状态，把完成的视频下载到对应组。

`shared` 共用提示词模式只使用全局提示词，每组原来的单独提示词仍保存但不拼接。各组的 `@男主 / @聆听者 / @音色` 分别解析为该组真正上传的资源引用，不会把第一组的图片套用给所有组。`combined` 模式保留全局提示词加本组提示词的原有逻辑。

这是工作台内的持续对话，不自动继承桌面 Codex 聊天的完整历史。切换项目保留聊天、模型选择与未发送文字；每轮工具操作固定使用发送时的项目和勾选组，运行中浏览其他项目不会改变该轮任务，下一条消息使用当前项目。附件仍按项目隔离，切换时清空待发送附件。聊天统一保存在工作空间根目录 `agent-chat.json`；仅点击“开启新对话”才归档为 `agent-chat-*.json` 并清空当前会话。首次使用新版会合并各项目现存聊天并标注来源，原文件不变，已显式归档的旧会话不自动导入。现有组图、提示词、人物绑定、音色和任务记录仍从本轮项目读取。

## 直接接口，无需 Computer Use

`dialogue_tool.workflow_api.WorkflowAPI` 是结构化业务入口。Agent 的动态工具与 CLI 使用相同入口；桌面、Agent、CLI 的主要写操作使用项目锁防止并发覆盖。修改组提示词还要求读取时的 revision，数据已变化时拒绝陈旧写入。

```powershell
# 输出全部工具的参数结构
.venv\Scripts\python.exe -m dialogue_tool workflow-schema

# 读取项目真实状态（稳定项目 ID 从工作台项目记录获取）
.venv\Scripts\python.exe -m dialogue_tool workflow PROJECT_ID read_project

# 参数从标准输入读取，避免 shell 引号破坏多行提示词
Get-Content -Raw -Encoding utf8 request.json | .venv\Scripts\python.exe -m dialogue_tool workflow PROJECT_ID update_groups --arguments -
```

`request.json` 示例：

```json
{"expected_revision":"READ_PROJECT_RETURNED_REVISION","updates":[{"group_id":"STABLE_GROUP_ID","prompt":"@男主自然说话，@聆听者安静倾听，不要字幕。","male_side":"a"}]}
```

工具覆盖：读取项目、查看实际 A/B 图、修改提示词与角色/音色绑定、生成配置、明确范围批量准备、报价、请求提交确认卡、按原 ID 查询/下载、执行单、新轮次、拆解、本地矩形修复、导出。收费批准不暴露为 Agent 工具，只有界面确认按钮能批准对应确认卡。

App Server 的线程和每轮均禁用环境访问，仅提供工作台动态工具，不依赖模拟点击或 shell 操作素材。不复制 OAuth 令牌，不把完整协议或图片 base64 写入聊天记录。模型请求会使用 Codex 额度；即梦生成使用另行登录的即梦账户和积分。

### 常驻连接与耗时

启动工作台会在后台连接一次并缓存模型目录，切页、切项目、开启新对话不会重新启动连接。已连接时显示状态标识，真实断开后由用户点击“重新连接 Agent”，不会自动重放任务。聊天面板显示当前阶段、总耗时及阶段等待时间，执行记录保存各工具耗时。

重建模型线程仅附带最近12条、最多16000字符的完整消息，全部历史仍保留；用read_chat_history的query和newest_first检索旧台词。看图在exec中先提取data:image并调用image()，禁止将原始图片字符串送入text()。图片仍按App Server的inputImage返回，参照 https://learn.chatgpt.com/docs/app-server 。


## 2026-11-13 H3首次任务基准

豪哥H3项目采用 `h3-first-v1`，来源优云智算2026-11-07首次任务 `01a1b66b-899c-748e-8270-273c305a0ea8`（本地837b756d），不是后来的f071c066或313fb518。基准保存在 `dialogue_tool/resources/h3-first-v1/`：原创作提示词、原8.83秒MP3音色、shared、15秒768P16:9、Context-IR开启、preserve_prompt=true、audio_first=false。只逐组替换A男主/B聆听者图片，不自动补人物前缀。基准模式阻止提示词、参数、音频漂移；明确要求新方案后才切换custom。

选择H3及新轮次自动为豪哥项目应用基准；旧提交和历史不改。无任务旧项目可用apply_h3_baseline。实际图片优先修复图，没有水印字幕的原图可保留。Agent逐图查看，有字幕水印则清理并复看，然后record_reference_review记录当前文件SHA256；更换文件后必须复查，不能因为有修复文件就自动视为合格。清理检查由Agent完成，不要求用户额外确认，也没有音色试听门槛。界面“检查实际输入”及付费卡显示实际图片、音频和最终绑定提示词；提示词属于提交原文，平台Context-IR仍会优化。已有付费任务继续按原ID查询，不因应用基准重新提交。

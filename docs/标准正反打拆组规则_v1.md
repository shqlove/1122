# 标准正反打拆组规则 v1（2026-11-02）

## 业务目标与优先级
输入视频，尽可能找出**每一段独立的连续人物交流**；在每段中按不同交流对象分别输出适合图生视频的原图 A/B，同一人物组合输出一组。
质量优先于凑数量。当前严格限定标准正反打，不接即梦，不做拼接，也不做配音/唇形同步。

## 两阶段语义
前置人物筛选（2026-11-05 更新）：《插翅难逃》以张世豪（豪哥）为固定主角。初筛、最终选图复核都附上用户确认的角色参考图，先对照再判断实际交流。参考图不能作为当前视频的 A/B 或范围索引；不得将模型猜测自动加入参考库。

角色匹配与对话质量分开处理：
- `matched`：对照正例确认，记录 A/B 位置及依据，保留。
- `not_matched`：有参考依据确认不是目标角色，排除。
- `uncertain`：包括完全无法判断、没有可用正例、缺少匹配依据，仍保留合格对话图片组，默认确认和勾选，显示“人物不确定 · 请检查”；用户可点“取消确认”，取消后不参与批量生成。
- 没有独立反打或画质不合格仍按原质量规则排除，不用角色不确定状态掩盖质量问题。

参考库保存在数据目录 `character-references.json`，按角色名称存放 `file/role/confirmed_by_user`，图片随库保存在数据目录。当前张世豪正例来自用户确认的第4组B图；第1、7组B图是用户纠正的反例。仅加载用户确认且文件存在的参考；缓存包含参考图片内容摘要，替换参考图会重新分析。其他角度须经用户确认后补充。

导入路径或项目名含“插翅难逃”时默认启用；已有项目未设置人物条件时同样适用。显式 `analysis_filter.required_character` 可指定其他主角，显式空对象可关闭筛选。既有配组不自动重做。模型匹配仍可能误判，一张正例不能覆盖所有造型和角度。

1. **先找连续对话片段：** 目标角色定位后，扩展命中或不确定镜头前后各两个镜头；分批查看这些镜头的代表图，长镜头按最长12秒窗口补点，发现人物交流，记录起止范围和人物身份锚点；把同一交流中多次 A/B 切换的重复提议合并。不同场景/时间的独立交流不合并。同场不同人物组合的独立交流分开。一对多逐个输出不同交流对象，允许共享目标角色截图。
2. **再挑最优 A/B：** 在片段时间范围内跨多个镜头寻找候选，使用两张人物锚点防止身份错换；最终二次验证只返回一对合格镜头。片段很长时有候选数量上限（24 张），不保证最佳帧一定入选。

## 全流程提速与并行筛选规则（2026-11-06）

- 人工协作筛选存在多个独立批次或图片组时，使用多个 subagent 同时看图，默认 3 个工作者。主 agent 统一分配、汇总去重和处理结论冲突。
- 所有工作者使用同一份人物正例、反例、网络辅助图和角色筛选条件。任务包含稳定组 ID、原片时间点和待检查截图，结果记录匹配状态、目标人物所在侧及判断依据。
- 扫描对视频执行全帧镜头检测，每镜头选择代表图定位目标角色，交流识别采用相关区域代表图，最终选图从交流范围内的完整候选池挑选。读取相邻目标帧时使用短距离连续解码，减少重复定位开销，并核对目标帧及时间点。
- 软件内初筛默认使用 3 个独立 Codex CLI worker，按连续时间分片并行。每个分片内按顺序处理批次并传递 `previous_summary`，保留批次间重叠帧。后续分片从前一批次 warmup 获取边界上下文，再处理本分片。主流程最后统一汇总、合并跨批次片段和去重。
- 最终 A/B 复核默认由 3 个独立 Codex CLI worker 并发处理，使用统一人物参考和各段的身份锚点选图。
- 缓存、使用量、进度和最终结果由主线程汇总写入。限流或失败后停止新增派发，收集已在执行的任务并保留成功缓存，继续分析时复用有效结果。
- 原图准备先按唯一帧去重，再使用 2 路并发提取，并复用视频 probe 信息。输出保持原尺寸，画质、人物匹配和标准正反打的验收要求继续适用。
- 角色身份不确定的合格对话组仍保留，默认确认和勾选，并显示人物不确定提示，交由用户手动取消确认。
- 并发数量受任务数量、服务限流和本机资源影响。分别记录扫描、初筛、去重、复核、原图准备的阶段耗时，以及并发完成数、缓存复用和识别质量。完整长片的耗时与质量需要用真实素材端到端验证。

## 明确通过
- 同一段连续交流中两个**不同真人**的独立镜头，构成标准正反打；A/B 必须是不同人物的独立画面。自动切镜编号可能漏分，编号相同的画面须依据逐图复核判断。
- 两侧人物脸部可见，优先正脸或小角度侧脸、中近景、无遮挡、自然表情、清晰、字幕不挡脸。
- A/B 仍是原片提取的完整尺寸画面，保留来源秒数、原片不被改动。
- 同一人物对反复切换只输出一组；隔开后形成新的独立对话可另起一组。

## 自动排除（不交给客户人工补选）
- 只有同框、只有单人镜头、没有独立反打；同一个人两张表情或两个角度冒充 A/B。
- 严重挡脸、背影、过度侧脸、过渡模糊、多人群像，找不到另一侧合格画面。
- 无法确认是两个不同对话人物、不同场景的镜头拼在一起、缺乏交流关系证据。仅目标角色身份不确定时按上述规则保留。
- 模型返回空 pairs 或标记 needs_review=true，一律跳过，不进入客户需要操作的“待确认”列表。

每个经过 A/B 二次复核的片段写入 `dialogue_segments`：
`index/start_seconds/end_seconds/anchor_a/anchor_b/status`；
排除时另存 `reason` 到 `excluded_dialogues`。
这份记录用于审计失败候选，并**不等于视频所有真实对白的清单**。

## 非目标、边界与验收
- 第一版不人工修复缺失的反打，不从双人同框自动裁切单人，不生成/拼接视频。
- 界面中保留旧任务和用户手动加组的待确认功能以兼容历史项目，但自动拆解不再给客户生成这类待办。
- 当前用视觉推断交流关系；没有语音识别和完整人工标注，无法保证所有对白场景被发现。
- 验收应使用真实视频人工逐段标注参考集，统计：真实合格段数、自动识别数、漏检数、错误配组、有效组脸部质量和去重错误。**不要只看最终输出组数。**
- 新算法与 Codex 的完整长片实测尚未在这次规则更新中完成，需单独做端到端验收。
